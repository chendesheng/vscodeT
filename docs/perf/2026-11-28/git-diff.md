# Git diff opening and interaction profile (2026-11-28)

Baseline `3c5667c1`, Zig 0.17 Debug, macOS ARM64. The opt-in diagnostic uses
real temporary Git repositories, the snapshot worker, the actual diff editor
and a 160×55 in-process frame. Both runs use a thread-safe DebugAllocator
without stack traces, matching the normal application heap. The older full
matrix in `docs/diff-view-audit.md` uses a page allocator instead; do not
compare its wall time directly to these measurements.

## Dense Myers diagonals

Pinned VS Code `e31c2e52f563620846caab877103f630ea361b9c`,
`src/vs/editor/common/diff/defaultLinesDiffComputer/algorithms/myersDiffAlgorithm.ts`,
uses `FastInt32Array` for furthest-X values and `FastArrayNegativeIndices`
for snake paths. The Zig version used two `AutoHashMapUnmanaged` instances;
macOS `sample` during the worker's computation showed substantial time in
hashing, `getOrPut` and hash-map lookup for every diagonal. The arrays are
now contiguous positive/negative vectors, grown geometrically with the
active diagonal band. Cached sequence lengths and the just-computed furthest-X
value avoid repeated virtual calls and lookups. The O(ND) search, tie
selection, timeout signal and traceback are unchanged.

Matched 10,000-line text file, every tenth line changed (1,000 exact hunks),
advanced diff, 5 s budget, move detection and wrapping off:

| Stage | Before | Dense arrays |
| --- | ---: | ---: |
| Git acquisition | 22.5 ms | 31.0 ms |
| Worker incl. acquisition/handoff | 2,400.7 ms | 175.7 ms |
| Mount | 173.7 ms | 176.7 ms |
| First frame | 21.3 ms | 22.5 ms |
| Total open | 2,595.9 ms | 375.1 ms |
| Scroll median / p95 | 2.61 / 3.30 ms | 2.69 / 3.05 ms |
| Total backing allocs to open | 36,906 | 36,902 |

Both results contain exactly 1,000 hunks with `timeout=false`. The worker
is 13.7× faster and total open 6.9× faster. The allocation count barely
changes because the previous hashes were reused but their CPU cost was
paid on every diagonal visited; this is not an allocation leak fix.

## Applying inner-editor options before attachment

For a 1,357,380-byte / 36,300-line TypeScript file, every 200th line
has a short comment appended (182 exact hunks). A second profile with
Myers already fixed found 905 main-thread samples under the worker reply's
mount path, including repeated `ProjectedViewModelLines.constructLines`
invoked from `Editor.attachModel`, `View.init`/`setScrollbarWidth`, and
later diff layout. The port was constructing default wrapped projections
of both entire models even with `diffEditor.wordWrap=off`. VS Code's
`DiffEditorEditors._adjustOptionsForLeftHandSide`,
`_adjustOptionsForRightHandSide` and `_adjustOptionsForSubEditor` supply
these values before the code editors receive models. The port now sets
wrapping, read-only, gutter, folding and status-row options before attachment.
The normal run-time option-update/layout path is retained.

| Stage | Dense arrays only | Early options |
| --- | ---: | ---: |
| Worker | 177.6 ms | 173.1 ms |
| Mount | 966.3 ms | 270.2 ms |
| First frame | 440.7 ms | 434.4 ms |
| Total open | 1,584.7 ms | 877.9 ms |
| Backing allocs to open | 153,596 | 47,536 |
| Requested bytes to open | 231.6 MB | 174.4 MB |
| Scroll median / p95 | 10.27 / 12.02 ms | 10.19 / 14.04 ms |

Both runs produce 182 hunks without timeout. Mount is 3.6× faster;
106,060 backing allocations are eliminated. The tracked allocator returns
to its initial live-byte count after window disposal. Initial frame still
builds both bracket trees and tokenizes the viewports; the frame and scroll
costs are not eliminated by either fix. A working-file input can also create
an extra editor projection during resolution in the current port. These
remain separate from the confirmed Myers/option-order regressions.

The combined final benchmark reran both fixtures (2/2 passed): the
1,000-hunk text diff opened in **310 ms** (166 ms worker, 122 ms mount),
and the 182-hunk TypeScript diff opened in **886 ms** (175 ms worker,
271 ms mount). The final code-diff scroll median/p95 were 10.12/11.72 ms.
Both runs returned all tracked live bytes at window disposal.

## Reproduce

```sh
zig build bench-open -Dbench-filter='benchmark: Git diff allocation profile'
zig build bench-open -Dbench-filter='benchmark: Git diff code allocation profile' -Dbench-file=/path/to/large.ts
```

The first fixture is generated by the benchmark. The second reads the input
file, writes a temporary Git base, appends a short comment on every 200th line,
and opens the two actual resources. The benchmark measures open and 50
scroll, 50 pointer-move and 50 key interactions; it does not measure terminal
emulator presentation latency. Neither run compares graphical VS Code speed.

The focused Myers (6/6) and diff-widget (63/63) tests passed, including new
signed index/growth, exact separated changes, and pre-layout option coverage.

Final native `zig build test --summary all`: 48/48 steps succeeded,
3,894 editor/workbench tests passed and 66 skipped; UI and standalone
TextMate suites reused their successful cached results. `zig build`,
`zig build check-workbench`, `zig fmt --check`, and `git diff --check`
passed. The fixture runs are local macOS checks, not cross-platform CI.
